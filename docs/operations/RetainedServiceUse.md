# Live four-input capture and one-use consumption

`historical.retained_service_use.use` connects the existing four-input reader to
a retained consumed-attempt record. It is a library for trusted host code and
has no root, reset, permission, Docker or command CLI. The legacy audit-only use
purpose and its reader remain separate.

Before capture it freezes the exact plan, roots, selection/manifest/checkpoint
and accepted CI/local-Sonar record bytes. It checks the four-input metadata
through the existing reader. A distinct exclusive, flushed attempt is retained
before source/runtime admission or any artifact open. Source, Python executable,
actual own image/birth, input-directory identity and record handles remain live.
The original 108-second operation clock is not restarted by capture or dispatch;
wall rollback and expiry also refuse a returned result.

Capture consumes its one slot before opening the four selected artifacts. Only
the same live object on its creating process/thread can pass the frozen serialized payload once to the callback
supplied by trusted host code. Callback errors, partial/lost responses, expiry or
oversized results consume that slot. Copied/foreign/closed objects cannot adopt
the live records or repeat capture. Reports do not reconstruct a capability.
There is no action or callback supplied by JSON.

The listed source hashes and pinned gate-record semantics are checked. This
does not authenticate the origin of those records, an existing user consent,
transitive loaded code/dependencies, a native consumer process or its returned
result. Local consumed records do not provide independent anti-rollback custody.
The image/probe/configuration commitments are frozen plan fields, not proof that
a native process actually used them.

The native adapter must keep this context alive through the exact fixed
native consumer, independently bind its process/private transport and measured
image/configuration, and exercise that same route with generated data and the
existing recovery targets before any original artifact read. This library does
not yet make the original executor ready. Do not replace that work with an
unrelated generated-only service scope or infer launch authority from a PASS.

The `v2-retained-service-use` test route now connects the same generated four
artifacts to the existing PostgreSQL/immudb/Server target through a private
parent/child pipe. The actual PowerShell parent retains its original in-process
Docker custody objects; no process or Docker ownership is adopted from JSON.
The Python child holds the consumed-use context through transfer, live status,
bounded result, context close and observed process exit. Before capture, the
parent builds its owned public image and creates disposable configuration;
their image/probe/configuration commitments enter the captured plan. The target
reconstructs and compares the configuration pin before native allocation.
Work checks include the admission peer; cleanup continues to use the original
custody objects even when admission is lost. Removal is not gated on a live
work channel. Four generated source paths are replaced after private transfer.

This route uses explicitly generated CI/local-Sonar parser fixtures. Their PASS
fields are not real run attestations or authenticated consent. It therefore
keeps `gateOriginAuthenticated`, `nativeResultAuthenticated` and
`originalExecutorReady` false. Its controller-loss and expiry cases, Linux
native execution and current CI/local Sonar acceptance must be verified before
this prototype can enter the original-data path. Unit transport success alone
does not prove native cleanup after a controller failure.

The `v2-retained-service-use-loss` route requests the child's own exit only
after both PostgreSQL restores and inventory checks. A generated-only mode is
accepted only under this repository's exact UUID fixture path. The held child
must exit 37; the next live-work check must refuse before audit restoration or
Server launch. The surviving PowerShell owner removes both target containers
and its image using its original custody objects. No caller-selected PID is
signalled. `v2-retained-service-use-expiry` instead waits for the original
108-second admission timer and actual child exit. It never replaces the clock,
shortens that deadline or renews a lease. These three profiles are mandatory in
the existing 15-minute retained Linux CI job; its deadline and the six-job
aggregate remain unchanged.

On Linux these three fixture profiles start their actual PowerShell owner from
a private copy of the selected public runtime, using the existing runtime
fixture helper. Its entrypoint hash is checked; host permissions are not
changed. The new process creates and retains its own native custody objects.
The wrapper does not adopt Docker replies or clean resources by copied IDs.
Preparation failures expose only a closed stage name (metadata, parent runtime
or parent identity), never the input bytes or an arbitrary exception message.

Before host admission, the same target now stops PostgreSQL and requires a
typed connection refusal with all three host ports still closed, then restarts
that same database process. It similarly stops its own immudb daemon, observes
its exit, refuses host admission, and restarts immudb against its existing data.
Both restarts use the original fixed startup arguments and owned namespaces.
Two successful host start/stop cycles then use the same frozen expectation and
configuration. Both signed audit tips and final full database inventories must
remain unchanged. No test event is inserted and no writer admission is granted.
The strict, historical and live-use native profiles require these backend and
host restart assertions. The75-second work window,108-second admission,
256 status bound and15-second observed native calls are unchanged.

Portable tests use only generated files. They require real own process identity,
four-file capture, flushed pre-open consumption, frozen packets, refusal after
source/record/owner loss, original-clock expiry before/after capture or return,
and non-retry after capture/consumer failures. Existing consumed-record and
audit-only contracts remain regressions.

Original backups, credentials/private PKI, provider/identity material and VPS
are not used. General creator/guardian/daemon/host loss, original release/build/
configuration/key lineage, independent WORM/actors, human/physical Agent and
full recovery RPO/RTO remain open. Phase 7 and draft PR #2 stay open.

The live native client and parent data-stage lifecycle are now shared libraries
(`RetainedNativeClient.ps1` and `RetainedDataStageHost.ps1`). The generated route
uses those same fixed commands, ownership objects, time limits and cleanup.
The shared host returns a neutral data-host schema; only the generated wrapper
claims that generated paths were replaced and no original files were read.
Its optional after-capture callback is restricted to the exact UUID fixture
directory before any input opening. Outside-root attempts are rejected in all
three modes. This callback must never be supplied for original inputs.

`retained_expected_inventory.py` maps three pinned metadata packets (selection,
coherent capture and accepted database report) into the existing native target
expectations. It performs no file reads or execution. It reconciles exact dump
hashes/lengths, source declarations, database inventory/security digests and the
stable audit point. Historical metadata does not contain the later additional
security digest: the fresh-target-role-policy-v1 expectation is explicitly a
target policy, never a claimed original measurement. Twelve portable tests
cover mismatched metadata, mutable buffers, invented source measurements and
forbidden path/permission/provider/identity fields.

These libraries and generated lifecycle tests do not yet supply the complete
fixed trusted operator entry or transitive code/command/resource inventory.
Original executor readiness and original recovery remain false. The four
previously authorized original archives are not opened by these tests.
