# Independent retained public-probe cleanup

The independent parent now owns the actual retained controller's process fence
and the successful image-build, stopped-copy and sleep-worker create replies.
The fixed child publishes only public code, keeps its original 58 publication
descriptors, and uses the existing exact typed image/readback/runtime bindings.
The parent holds a separate 58-file public reference and verifies every context
and readback byte. Eighty-one fixed source inputs are pinned; preparation and the
separate fixed Python guardian pin 63 public inputs. The legacy forty-input
native publication and four extra runtime-input inventories keep their names.

This profile has its own fixed header with the Docker executable hash. The
original context-only header still admits exactly its original runtime roles
and does not start Docker. Private tool directories precede interpreter/system
directories. The only extended stages are a bounded image/readback frame plus
archive, a runtime-intent/preparation reply, a fixed runtime observation and its
typed binding reply. A fixed cancellation frame works at either binding stage.
The original context-only transport keeps its fixed 55-second whole-operation
window. The extended profile uses that same startup window until context
admission, then the minimum of the original retained/image expiry with a matching
fixed monotonic end. This does not renew either existing 60-second source window;
the exact end/origin is retained in its own immutable admission record. Source
pin checks recheck the clock before returning data.
Bounded writer/reader threads check the actual controller and fixed deadlines;
there is no generic command, path, endpoint, environment or secret channel.

The parent measures all three fixed cached bases itself, builds only the fixed
untagged public recipe, and obtains complete canonical immutable IDs directly
from its own bounded CLI calls. The child cannot supply an image/container ID
as parent cleanup authority. It receives the parent's checked image/readback,
creates the existing unobserved retained runtime and preparation, and keeps
preparation live until the complete parent create reply reaches the child.
Preparation closes immediately before the one consumed runtime observation;
the same original publication descriptors remain held through the handoff.
The child executes no Docker command and starts no service.

The fixed `run()` lifecycle prepares, watches and closes its own controller.
Leaving its context after a failed handoff attempts rollback of known own
resources before closing process/file capabilities. A consumed cleanup is never
replayed. Complete own creation replies remain usable for that rollback even
when the child dies before its final typed runtime binding.

Own replies have an in-process creator brand and are tied to that exact client,
fixed input hash, actual parent/controller identities, full ID, creation interval
and observation. Exclusive flushed start/build/resource/bound/delete/result
records retain failure/replay consumption. Returned dicts and serialized records
cannot recreate these live creator objects. All current record bytes retain
their exact canonical JSON plus one LF. No reset/restart adoption is provided.

The retained test worker uses the unchanged 660-second sleep command and fixed
384-MiB, one-CPU, 128-PID, UID/GID 3322 sandbox with read-only root, no network,
no capabilities, no-new-privileges, core-dump limit and two fixed noexec tmpfs
mounts. The parent starts a five-second ready cleanup lease after the typed handoff,
bounded by the original admission expiry. Its independent watcher observes its owned actual
controller or the lease, then freshly inspects the full immutable resource IDs
and compares every field with its own sealed profile before deleting. If an own-process image query fails during termination, a fixed three-second wait requires the actual owned exit signal; a still-live or changed identity refuses cleanup. The
stopped readback copy is never started and has its own stricter small profile.
The image removal uses the full ID and no parent pruning; cached bases must
remain unchanged and owned IDs must be absent from successful bounded listings.

Cleanup uses the parent's successful creator facts and fixed profile/creation
window. It does not reuse an old timestamp as a new observation or bypass the
original admission checks. The existing admission wrappers still require their
same wall/monotonic windows. Static profile parsers grant no authority. The
ready guardian can finish cleanup during its separate 75-second cleanup window
after the child/admission has expired; no child capability is revived. Controller closure always requires all owned process members absent. If the original source admission expired before closure, forced own-fence closure is recorded separately from graceful descriptor acknowledgement; the fixture does not demand an expired channel remain live.

Portable contracts require positive typed bindings and refuse altered lineage,
foreign IDs/observations, arbitrary fields, malformed/partial replies, changed
persisted/held facts, expired admission, unsafe profiles, foreign creator objects
and replay. Linux CI reuses the existing public publication/reference fixture
for eight actual controllers: lease expiry, controller death while the parent
waits, death after the own complete create reply before runtime binding, a real
original admission expiry, foreign observation, lost create reply,
partial create reply and CLI inspection failure. A standalone fixture supports
only those fixed cases for Windows Docker Desktop validation. No original input
or restored process is involved.

A lost/partial reply remains unknown to the guardian; no name lookup adopts its
resource and no positive cleanup result is returned. The negative test fixture
captures the complete inner reply at a separate creator call site, then disposes
its own test resources under fresh profile checks. This test-only disposal does
not reset or authorize the consumed guardian attempt. CLI/foreign-observation
failures likewise refuse deletion and retain consumption before fixture disposal.

Guardian/daemon/host death, paused or altered resources, pre-receipt crashes,
general bootstrap/compiler escaped sessions and independent rollback-resistant
custody remain open. The separate Python worker's thirty-second passive fallback
does not apply to this 660-second retained worker. There is no full RPO/RTO,
original service/config/provider/private-PKI recovery, issuer/token operation or
production deployment claim. Phase 7 and draft PR #2 stay open, including WORM,
independent people, post-restore human login, physical Agent and revocation.
